# Architecture

Describes what exists now. Planned components are in [PLAN.md](PLAN.md) and move here as they land.

## Packages

- `server` — Fastify 5 API. Requests and responses are validated with zod through `fastify-type-provider-zod`, which also produces the OpenAPI 3.1 document at runtime via `@fastify/swagger`. Entry points: `src/main.ts` (listen), `src/app.ts` (`buildApp`, used by both main and tests), `src/openapi.ts` (writes the document to the contract package).
- `packages/api-contract` — `openapi.json` emitted by the server, `src/schema.d.ts` generated from it by `openapi-typescript`, and `createProjektorClient`, a thin wrapper over `openapi-fetch` that injects a bearer token on every request. This is the only way clients written in TypeScript talk to the server; Kotlin and Swift clients will be generated from the same `openapi.json`.
- `android/` — Gradle project with `:core` (client generated from the contract at build time, session store, auth), `:player`, `:app-mobile`, `:app-tv` (Kotlin, Compose, Compose for TV, Media3). Not part of the pnpm workspace; see docs/android.md.
- `web` — React 19 + Vite + TypeScript. TanStack Query for server state, react-router for routes, the generated `@projektor/api-contract` client for every call. Same-origin in production (the server serves `web/dist`), proxied through Vite in development. See Web app below.

## Configuration and data directory

`server/src/config.ts` parses the environment with zod into a `Config` and creates the `DATA_DIR` layout (`projektor.sqlite`, `images/`, `subtitles/`, `transcode/`). `buildApp` installs a JSON content-type parser that treats an empty body as no body, because generated clients (the Kotlin one included) send body-less POSTs with a JSON content type and Fastify's default parser would answer 400. It takes a `Config`, opens the database, and decorates the Fastify instance with `config` and `db` so routes reach both through `app`. Tests get an isolated `Config` in a temp directory from `test-utils.ts`.

## Authentication

`server/src/auth/` holds the pieces. `pin.ts` hashes PINs with Argon2id. `tokens.ts` generates 32-byte random bearer tokens and hashes them with SHA-256 for storage, so a leaked database does not leak usable tokens. `service.ts` is `AuthService`: setup, profile listing, login with the failed-attempt counter and lockout, token resolution, and session revocation. `plugin.ts` registers the service on `app.auth`, adds an `onRequest` hook that rejects any `/api` request without a valid token unless the route sets `config.public`, and exposes `app.requireAdmin` as a preHandler for admin-only routes. Routes live in `routes/auth.ts`.

Login is rate limited per IP with `@fastify/rate-limit` (registered with `global: false`, applied only where a route sets `config.rateLimit`). Lockout is per profile: five wrong PINs lock it for fifteen minutes.

## Libraries and scanning

`server/src/library/service.ts` is `LibraryService`: create (validates every path is a directory, stores resolved and de-duplicated paths), list, get, delete. `walker.ts` is an async generator that walks a root breadth-first, yields files whose extension is in `VIDEO_EXTENSIONS`, skips dot-files and dot-directories, and reports unreadable directories through a callback instead of aborting. `scanner.ts` reconciles a library: for every walked file it inserts a new `media_files` row or, when size or mtime differ, updates the row and clears `probedAt` so the file is probed again; rows whose file was not seen are flagged `missing`, and a flagged row whose file reappears is unflagged. The scan returns counts plus the ids of files that need probing. Routes are in `routes/libraries.ts`; mutations require admin.

`scan-runner.ts` runs scans in the background, one library at a time: walk, probe, identify, match, updating a per-library `ScanStatus` at each phase boundary so clients can show progress. Requests for a library already queued are dropped; a request while that library is running schedules exactly one rerun. `watcher.ts` uses chokidar on every library path (ignoring the initial listing, waiting for files to stop growing, filtering to video extensions and non-hidden paths) and, after a quiet period of `SCAN_DEBOUNCE_MS`, asks the runner to scan that library. Watchers start with the app, are added and removed with libraries, and can be disabled with `WATCH_LIBRARIES=false`. `watch()` resolves only after chokidar's initial directory scan, because with `ignoreInitial` a file that appears during that scan is treated as pre-existing and never reported. Shutdown closes the watchers and waits for a running scan.

## Probing

`server/src/media/ffprobe.ts` runs `ffprobe -print_format json -show_format -show_streams` through execa with an argument array (never a shell string) and a 60 second timeout, validates the JSON with zod, and normalises it: a canonical container name (ffprobe reports demuxer lists like `matroska,webm`, so the file extension breaks ties), duration in milliseconds, overall bitrate, and one entry per video, audio, or subtitle stream with codec, language (`und` becomes null), title, default and forced flags, dimensions, and channel count. Attached-picture streams (cover art) are dropped. `probe-service.ts` probes a list of file ids with a concurrency limit of 4, writes the result to `media_files` and replaces the file's `streams` rows in one transaction. A file ffprobe cannot read still gets `probedAt` set, with the error kept in `probeJson`, so broken files are not re-probed on every scan; a later change to the file clears `probedAt` through the scanner and it is tried again.

## Identification

`server/src/identify/scene-parser.ts` turns a file name plus its folder names into a `ParsedName`: kind (movie or episode), title, year, season, episode, and an `episodeEnd` for multi-episode files. Episode markers are matched first with our own patterns (`S01E02`, `S01E02-E03`, `S01.E02`, `1x05`, `Season 1 Episode 5`); `parse-torrent-title` then supplies titles and years and strips release tags. Folder hints fill gaps: a `Season NN` or `Specials` parent makes the grandparent the show title, and a Plex style `Title (Year)` parent overrides a bare movie file name. Every result carries a `confidence` that is `low` when it had to guess.

`fansub-parser.ts` handles anime libraries. It strips the leading `[Group]`, records a `(Year)` or `(Season N)` tag, drops every other bracketed tag, then finds the episode number from `SxxEyy`, the ` - NN` convention (with `v2` versions, `NN-MM` or `NN ~ MM` ranges, and `END` markers), `Episode NN`, or a trailing bare number. A season phrase in the title (`2nd Season`, `Season 2`, `S2`, `Part 2`) sets the season and is removed from `title` but kept in `searchTitle`, which is what AniList will be searched with. When no season is known the number is kept as an absolute episode.

`identifier.ts` links probed files to items. For anime files with only an absolute number, episodes group by show and `absoluteNumber` with `seasonNumber` and `episodeNumber` null until 1.8 maps them; they are listed directly under the show in the meantime. Movies group by library, normalised title (`sortKey`: lowercase, articles and punctuation removed), and year. Episodes group by show, season, and episode number; a file with no episode number gets its own row so it is visible for review. Seasons and shows are created on demand. Everything created here has `needsReview = true` until a metadata match confirms it. Files whose probe failed are left unlinked. The scan endpoint runs walk, probe, identify in that order.

`items/service.ts` is the read model behind `/api/items`: it maps the four tables to `ItemSummary` and `ItemDetail`, handles browsing by library kind, kind, parent, search, and review flag, and attaches files with their streams to movies and episodes.

## Metadata and artwork

`server/src/metadata/tmdb.ts` is a small TMDB v3 client over `fetch` (injectable for tests) that accepts either a v3 API key (sent as `api_key`) or a v4 read access token (sent as a bearer header) and validates responses with zod. `score.ts` ranks search results: Sørensen–Dice similarity over normalised titles, a bonus for a matching year and a penalty for a clearly different one, popularity as a small tiebreaker, and an acceptance threshold of 0.85. `matcher.ts` runs after identification: for every movie and TV show never attempted it searches, applies the top result when it clears the threshold (title, year, overview, tagline, genres, rating, runtime, poster, backdrop, `needsReview = false`), and otherwise records `matchAttemptedAt` so the item is not searched again on every scan. For shows it fetches only the seasons that have local files and fills episode titles, overviews, air dates, stills, and runtimes by episode number. Anime libraries are skipped here and handled by the anime matcher below. Two requests run concurrently; a 401 from TMDB drains the queue. `fake-tmdb.ts` is the canned server the tests run against.

`metadata/anilist.ts` is a GraphQL client for AniList (no key needed, 90 requests a minute, so the anime matcher runs one request at a time). `metadata/anime-matcher.ts` handles shows in anime libraries: it searches AniList with the show title, ranks results over the English, romaji, native, and synonym titles with the same scorer, and applies the top result when confident: AniList id, English title (romaji fallback), description with its light HTML stripped, genres, score out of ten, cover art as poster, banner as backdrop. AniList has no TMDB ids, so the matcher then searches TMDB TV with the AniList titles and year; when that clears the threshold it stores the TMDB id and `season-map.ts` maps every absolute-numbered episode onto TMDB seasons by cumulative episode counts (season 0 ignored), after adding the show's `seasonOffset`. Mapped episodes get season rows and then the same per-season episode fill as TV shows; numbers beyond the last season stay absolute-only. Without a TMDB key the show still gets AniList metadata and its episodes stay listed by absolute number.

`images/store.ts` caches artwork under `DATA_DIR/images/<2-char prefix>/<sha1 of source url>.jpg`. Originals are downloaded once at TMDB's `w780` (posters, stills) or `w1280` (backdrops) and normalised to JPEG with sharp; `/api/images/{key}?w=` resizes to 300, 780, or 1280 on first request and caches the variant next to the original. The route is public because `<img>` tags cannot send headers and the keys are unguessable.

`metadata/deps.ts` builds the TMDB client (if a key is set), the AniList client, the image store, and both matchers from current settings and `app.httpFetch`, the app's single outbound fetch. Tests pass a fake through `buildApp({ fetch })`, so the whole scan-and-match path runs against canned TMDB and AniList responses without touching the network. `metadata/fix-match.ts` powers manual correction: `candidates` searches the sources that apply to the item and ranks them with the same scorer, `apply` writes a chosen TMDB or AniList id through the matchers' `apply*` methods, and for anime a changed `seasonOffset` remaps the absolute episodes against the attached TMDB show.

`settings/service.ts` is a typed key-value layer over the `settings` table for the TMDB and OpenSubtitles credentials; the API only ever returns secrets masked.

## Playback

`routes/files.ts` is direct play: the original file streamed by id (never by path) with byte-range support so players can seek. `parseRange` handles closed, open-ended, and suffix ranges and rejects unsatisfiable ones with 416. HEAD returns the same headers without a body. Because `<video src>` cannot carry an `Authorization` header, the auth hook also accepts `?access_token=` on GET and HEAD requests only. `playback/decision.ts` is the pure function behind `POST /api/playback/decide`. The client sends a `DeviceProfile` (containers, video codecs, audio codecs, max width, max bitrate, preferred HLS segment container). The file's container, bitrate, and streams are checked against it: everything fits → `direct`; video fits but the container or audio does not → `remux` (video copied, audio copied or re-encoded to AAC); video codec, width, or bitrate fail → `transcode` to H.264. Asking for a non-default audio track forces at least a remux because direct play cannot switch tracks in most players. Every decision carries human-readable reasons. `playback/sessions.ts` holds HLS sessions in memory (file, profile, decision, start position, last access); remux and transcode decisions create one and return its master playlist URL.

`playback/ffmpeg-args.ts` builds ffmpeg argument arrays (pure, unit tested). A remux maps the video stream and the chosen audio stream, copies video (tagging HEVC as `hvc1`, which MediaSource and Safari require), copies or re-encodes audio to stereo AAC, drops subtitles and data tracks, and writes an HLS event playlist with 6 second segments as MPEG-TS or fMP4 (with `init.mp4`) depending on the profile. `playback/hls.ts` is `HlsManager`: it starts ffmpeg on the first playlist or segment request, writes into `DATA_DIR/transcode/<session>/`, authors the master playlist itself, serves ffmpeg's own index playlist and segments (waiting up to 20 seconds for a file to appear, answering 404 once ffmpeg has exited without producing it), caps concurrent ffmpeg processes (`HLS_MAX_PROCESSES`), stops sessions untouched for `HLS_IDLE_MS`, and removes their directories. Remux lets ffmpeg own the playlist because copied streams keep their original keyframes, so segment boundaries are only known once written (the first playlist request waits up to 8 seconds for ffmpeg to finish so short remuxes present as VOD); the transcode path controls keyframes and precomputes the playlist instead.

A transcode encodes H.264 (libx264 `veryfast` CRF 23, or `h264_vaapi` when hardware is enabled) with `-force_key_frames expr:gte(t,n_forced*6)` and scene-cut detection off, so every segment N covers exactly [6N, 6N+6) seconds no matter where ffmpeg started. The media playlist is therefore generated from the file's duration before any segment exists (`vodPlaylist`), and ffmpeg's own playlist is written to `ffmpeg.m3u8` and ignored. When a player asks for a segment that does not exist yet and is behind the current run's start, more than `HLS_SEEK_AHEAD_SEGMENTS` (default three) beyond the segment ffmpeg is writing next, or after ffmpeg has exited, the manager kills ffmpeg and restarts it at that segment with `-ss 6N` and `-output_ts_offset 6N`, so segments from different runs share one timeline and already written segments stay valid. Scaling to `maxWidth` and a `maxBitrate` cap come from the device profile. Transcodes are capped separately (`HLS_MAX_TRANSCODES`) because one costs far more than a remux.

`playback/hardware.ts` runs once on startup. With `HARDWARE_ACCEL=auto` it checks that the render node exists and then encodes a single synthetic frame with `h264_vaapi`; success switches every new transcode to the VAAPI path (GPU decode with `-hwaccel vaapi`, `scale_vaapi`, `h264_vaapi`), failure keeps libx264 and logs the ffmpeg error. `vaapi` forces the GPU path without testing and `none` forces software. The outcome is logged and exposed on `/api/health` as `encoder` and `encoderReason` so the deployment check is one curl.

## Subtitles

`subtitles/service.ts` runs during every scan after probing. For each changed file it records embedded text tracks (subrip, ass, ssa, mov_text, webvtt; bitmap formats are skipped) from the `streams` table and sidecar files beside the media whose name is the media's base name plus an optional two or three letter language code and an optional `forced` marker (`Movie.en.srt`, `Movie.de.forced.srt`). Rows are matched on source, stream index, and sidecar path so a rescan keeps existing conversions; OpenSubtitles rows (3.8) are never removed by discovery. `ensureVtt` converts a track to WebVTT with ffmpeg on first request into `DATA_DIR/subtitles/<file>/<subtitle>.vtt`; ffmpeg drops ASS positioning and effects and keeps basic italics.

Tracks surface in three places: `MediaFile.subtitles` on item details, `GET /api/files/{id}/subtitles`, and `PlaybackDecision.subtitles`. HLS sessions add one `EXT-X-MEDIA:TYPE=SUBTITLES` rendition per track to the master playlist, each pointing at a one-segment media playlist whose single "segment" is the whole WebVTT file, so AVPlayer and ExoPlayer render them natively. Because players resolve segment URLs relative to the playlist and drop its query string, a playlist requested with `?access_token=` is rewritten so every URI carries the token too.

## Progress

`progress/service.ts` keeps one `playback_state` row per user and item (movies and episodes only). `update` stores the position and marks the item watched once it passes 90% of the duration; the flag is sticky so a rewatch from the start does not un-watch it. `setWatched` sets the position to the end or deletes the row. `continueWatching` lists unwatched rows by recency. `nextEpisode` orders a show's episodes season-major with specials first and season-less anime by absolute number at the end, and returns the following one. `ItemsService` takes the caller's user id and stamps `progress` onto every summary and detail it returns, so clients never fetch progress separately.

## Live TV

`live/xtream.ts` is the Xtream Codes client: `player_api.php` for the account check (a wrong password is a 200 with `auth: 0`, mapped to an `auth` error), live categories and streams, VOD and series listings, and `xmltv.php` for the guide, parsed with fast-xml-parser into programmes with UTC ISO timestamps. Provider responses mix numbers and strings, so every field is coerced through zod. It also builds the provider stream URLs (`/live/`, `/movie/`, `/timeshift/`) that carry the credentials in the path; those never leave the server. `live/refresher.ts` reads `iptv.url` (falling back to `IPTV_URL`), `iptv.username`, and `iptv.password` from settings, refreshes on start, every six hours, and whenever an admin saves IPTV settings or calls `POST /api/live/refresh`, coalescing concurrent runs. Channels and categories are upserted and pruned; programmes are replaced. State (`refreshing`, `lastRefreshAt`, `lastError`, account status and expiry) is exposed on `GET /api/live/status`. `live/service.ts` is the read side: channels with what is on now and next, categories, and a guide window per channel. `live/fake-xtream.ts` is the in-memory provider the tests route `app.httpFetch` through. `LIVE_REFRESH=false` disables the schedule (tests).

`live/relay.ts` opens one provider connection per channel and fans the MPEG-TS bytes out to every subscriber (a viewer's response, the live HLS packager, and later a recorder), because IPTV accounts allow one or two concurrent connections. The connection closes a few seconds after the last subscriber leaves so a channel change back is instant (an idle relay is evicted early when a new stream needs its slot); a subscriber that stops reading is dropped once it has buffered 16 MB rather than stalling the others. `LIVE_MAX_STREAMS` caps concurrent provider connections. `live/live-hls.ts` runs ffmpeg with the relay as stdin and writes a sliding window of six 4-second segments (video copied, audio re-encoded to stereo AAC so MP2 and AC-3 channels play in browsers); sessions have their own registry, idle sweep, and directory (`transcode/live-<id>`), and share `HlsError` and `withToken` with VOD playback. `POST /api/live/decide` picks the raw relay for profiles that list the `ts` container and a live HLS session for the rest. The Fastify server is built with `forceCloseConnections` so shutdown cuts open streams instead of waiting for viewers.

IPTV Movies and IPTV Series come from the same refresh: `refreshCatalog` upserts VOD and series categories (ids prefixed `vod:`/`series:` in `live_categories`) and titles into `iptv_movies` and `iptv_series`, parsing the provider's name with `parseProviderTitle` ("EN - Sample Movie (2019) 4K" → "Sample Movie", 2019) and dropping titles the provider removed. After each refresh `live/provider-matcher.ts` searches TMDB for every never-attempted title with the same scoring as local files and writes the details and cached artwork; unmatched titles keep the parsed name with `needsReview` so the UI shows the provider's cover instead. `live/vod-service.ts` is the paged, searchable read side and fetches a series' episodes from `get_series_info` on first open (cached 24 h). Playback: `POST /api/live/decide` with `vodId` or `episodeId` returns `direct` when the device profile lists the file's container, pointing at `live/proxy.ts`, which passes the provider file through with the `Range` header and range response headers intact so players seek natively; otherwise it opens an HLS session of kind `vod` where ffmpeg reads the provider URL itself (seekable HTTP, so no relay) and writes an EVENT playlist. The provider URL carries the password, so it is redacted from the ffmpeg log line.

Recording (`live/recorder.ts`) is one more relay subscriber: the MPEG-TS bytes are written straight to `RECORDINGS_DIR/<channel>/<title> (<date>).ts` with a sidecar `.json` of the same record, no ffmpeg involved while capturing. A recording is created now, at a time, or for a guide programme (start at the programme's start or now, end at its end plus `RECORDING_PADDING_MS`); rows move `scheduled → recording → done | failed`. A scheduler tick every five seconds starts due rows and stops those past their end; stopping by hand keeps what was captured as `done`, cancelling a scheduled one removes it, deleting removes the files. On startup any row still `recording` is marked `failed` with its file kept and size recorded, and a scheduled row whose end has already passed fails as missed. When a recording ends, ffprobe measures the duration. Playback goes through `POST /api/live/decide` with `recordingId`: `direct` at `GET /api/recordings/{id}/stream` (byte ranges, serves the growing file while recording) for devices that play TS, otherwise an HLS session of kind `vod` where ffmpeg reads the local file. Because recordings and viewers share the relay, recording a channel while watching it costs no second provider connection.

Catch-up reuses all of that. `POST /api/live/decide` with a `programmeId` checks that the programme belongs to the channel, has ended, and falls inside the channel's archive window, then opens an HLS session whose relay pulls the provider's `timeshift.php` URL (`/timeshift/U/P/<minutes>/<YYYY-MM-DD:HH-MM>/<stream>.ts`). The start stamp is the programme's UTC start rendered in the provider's own timezone from `server_info.timezone`, which the refresher records on each run. Catch-up sessions are packaged as a growing EVENT playlist that keeps every segment and ends with `ENDLIST` when the provider finishes sending, so the viewer can seek anywhere already written. The decision carries `kind`, `durationMs` (the guide's length), and `title`; catch-up is HLS for every device since a raw TS is not seekable.

## Web app

`web/src/App.tsx` mounts the router inside a QueryClient. `Gate` sends first-run visitors to `/setup`, signed-out visitors to `/login`, and everyone else into `AppShell`, the top-nav layout (Home, Movies, TV Shows, Anime, Live TV, Search, and Settings for admins). `auth/store.ts` keeps the bearer token and profile in localStorage and notifies React through `useSyncExternalStore`; `api/client.ts` wraps `createProjektorClient` with that token, exposes `unwrap` to turn openapi-fetch results into thrown errors with the server's message, `imageUrl` for artwork, and `withAccessToken` for URLs the browser fetches on its own (video, subtitles). `PinPad` is the one input component that must work with a mouse, a keyboard, and later a TV remote.

Browsing is built from three pieces: `PosterTile` (poster or 16:9 still for episodes, progress bar, watched and needs-review badges, links to `/items/:id`), `Row` (a titled horizontal strip that renders nothing while empty), and `Grid`. `hooks/useItems.ts` wraps the API in TanStack Query hooks: paged library browse, recently added and continue watching per kind, search, item detail, children, next episode. `HomePage` shows continue-watching and recently-added rows per library kind so anime never mixes with TV; `LibraryPage` is the sortable, load-more grid behind `/movies`, `/tv`, `/anime`; `SearchPage` queries from two characters; `ItemPage` renders any kind with backdrop, poster, metadata, a Play or Resume action pointing at `/play/:fileId` (the player lands in 1.21), seasons or episodes for shows and seasons, the next episode for an episode, and collapsible file, stream, and subtitle details. Styles are a single stylesheet with CSS variables; layout uses grid gap only because the Tizen 5 browser predates flexbox gap.

Settings (`/settings`, admins only; others are redirected) has four tabs. Libraries lists each library with its last scan summary, polls the scan status while one runs and invalidates every cached query when it finishes, adds libraries by name, kind, and server folder, and deletes them after a confirm. Metadata stores the TMDB, OpenSubtitles, and IPTV credentials (the IPTV card also shows the live status: channel and programme counts, account state, last error, and a refresh button); the API only ever returns them masked, so the fields show `Set …1234` and accept a new value. Users lists profiles, adds one with a PIN and admin flag, deletes others, and lists the caller's own devices with a sign-out per device. Needs review lists every item still flagged from file-name identification with a search form (title and year) that calls the candidates endpoint and applies the chosen TMDB or AniList result, plus a season-offset field per anime show. `routes/users.ts` on the server backs the Users tab.

Playback lives under `web/src/player/`. `profile.ts` builds the `DeviceProfile` by asking the video element's `canPlayType` about codecs, so Safari reports hevc and ac3 while Chrome does not; direct-play containers are only `mp4` and `webm`, because browsers stall on large Matroska files even when they claim support, so MKV is always remuxed to HLS, and prefers fMP4 segments wherever MediaSource or native HLS exists. `HtmlVideoPlayer` wraps a `<video>` element behind a small interface (load, play, pause, seek, events) that the Tizen AVPlay implementation will share in phase 3: direct play sets `src`, HLS uses hls.js wherever MediaSource exists and the browser's own HLS only where it does not (iOS), because desktop Chrome answers `maybe` for the HLS MIME type but cannot play a live playlist; hls.js is given a patient load policy (30 s to first byte) since the server holds the first playlist request until ffmpeg has written a segment. `vtt.ts` is a small WebVTT parser and `SubtitleOverlay` renders the active cues itself, so subtitles look the same in every browser and on the TVs and we never depend on native track rendering. `player/prefs.ts` holds the two preferences the owner cares most about, the skip amount (3 to 15 seconds) and the playback speed, persisted in localStorage and validated on load. `PlayerPage` asks `/api/playback/decide`, loads the returned URL with the access token appended, reports progress every ten seconds and on pause, end, and unmount, switches audio tracks by asking for a new decision from the current position, exposes subtitle and audio pickers, forward and back buttons plus the arrow keys that jump by exactly the chosen skip amount (for a remux, `player/timeline.ts` decides whether a seek stays inside the part ffmpeg has written or opens a new session at the target, and the page keeps that session's start offset so times, the bar, and progress reports stay absolute), a speed selector applied to the video element, keyboard shortcuts (space, f, escape), and offers the next episode when one ends.

Live TV (`hooks/useLive.ts`, `pages/LivePage.tsx`, `pages/LivePlayerPage.tsx`, `live/channel-entry.ts`) is a separate section, not a library kind. The Live tab lists categories as chips and channels as rows with logo, number, name, what is on now with a progress bar, what is next, and a catch-up pill, refetching every minute so now/next stays right; an unconfigured server shows a pointer to Settings instead. The live player at `/live/:channelId/watch` asks `POST /api/live/decide` (browsers always get `hls`), loads the playlist with `live: true` so hls.js starts at the live edge, and releases the session with `DELETE /api/live/sessions/{id}` when the channel changes or the page closes. There is no seek bar. Up/Down (or the Ch − / Ch + buttons) step through the channel list with wrap-around, typed digits jump to a channel number after 1.5 s, G toggles a guide panel for the channel, Escape returns to the list. `channel-entry.ts` holds the pure neighbour and number-lookup helpers with unit tests. Live TV has three tabs (`components/LiveTabs.tsx`): Channels, IPTV Movies (`pages/IptvMoviesPage.tsx`: search, category select, poster grid of `IptvTile`s using cached TMDB art with the provider's cover as fallback, a detail page with Play), and IPTV Series (`pages/IptvSeriesPage.tsx`: the same grid, a detail page with season chips and an episode list). Movies and episodes play in the provider-file player (`LiveCatchupPage` with `source` `movie` or `episode`), direct when the browser plays the container and HLS otherwise. The live player has a ● Rec button (record this channel until stopped) and every guide programme that has not ended has ● Record (on air: until it ends plus padding) or ● Schedule (upcoming). The Recordings tab (`pages/RecordingsPage.tsx`) lists scheduled and made recordings with state badges, Stop, Cancel, Delete, and Play, polling every three seconds while anything is scheduled or running; recordings play in the provider-file player with `source` `recording`. Past programmes on a catch-up channel show a Watch link in the guide panel that opens `pages/LiveCatchupPage.tsx` at `/live/:channelId/catchup/:programmeId`: the same controls as the file player (skip back and forward by the chosen amount, speed, seek bar) over the catch-up HLS session, with `HtmlVideoPlayer.knownDurationMs` set from the guide so a forward skip is not clamped to the part of the EVENT playlist fetched so far.

The end-to-end suite (`e2e/`, Playwright) runs the built app against the real server: `e2e/start-server.mjs` boots the API with a temporary data directory and `WEB_DIST` plus the fake IPTV provider (`server/src/live/fake-xtream-server.ts`, port 8098, looping the sample movie as a live channel with a 2 s GOP), specs seed libraries from the fixtures through the API, then drive the UI. It runs in branded Chrome rather than Playwright's Chromium because the latter ships without H.264 and AAC decoders, so real playback could not be asserted.

## Deployment

`deploy/Dockerfile` is two stages. The build stage carries python3, make, and g++ so better-sqlite3 and argon2 can compile when no prebuilt binary matches, installs the workspace with pnpm, compiles the server with `tsc` (tests, fakes, and the OpenAPI emitter excluded via `tsconfig.build.json`), builds the web app, and uses `pnpm deploy --prod` to produce a self-contained server directory. The runtime stage is `node:22-bookworm-slim` (pnpm 11 needs Node 22.13 or newer, so both stages use it) plus Debian's ffmpeg, libva, `vainfo`, and, on amd64, Intel's `iHD` (non-free) and `i965` VAAPI drivers, with `tini` as PID 1 so ffmpeg children are reaped. The server runs as `node dist/main.js` with `DATA_DIR=/data`, `WEB_DIST` pointing at the built web app, and `HARDWARE_ACCEL=auto`. `deploy/docker-compose.yml` publishes port 8096, mounts the data directory and the three media folders (read-only), and passes `/dev/dri` through. A Docker `HEALTHCHECK` polls `/api/health`.

## Data model

SQLite via better-sqlite3 with Drizzle ORM. WAL journal, foreign keys on. Text UUID primary keys, ISO 8601 UTC timestamps, milliseconds for durations.

| Table                          | Holds                                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `users`                        | Profiles: name, Argon2id PIN hash, admin flag, avatar colour, failed-attempt counter and lockout time        |
| `sessions`                     | Bearer tokens (stored as SHA-256 hashes) with device name and last-seen time                                 |
| `libraries`, `library_paths`   | A library has a kind (`movie`, `tv`, `anime`) and one or more folder paths                                   |
| `movies`                       | One row per movie item with TMDB metadata and artwork keys                                                   |
| `shows`, `seasons`, `episodes` | TV and anime share these; `shows.season_offset` and `episodes.absolute_number` exist for anime mapping       |
| `media_files`                  | One row per video file: path, size, mtime, probe results, `missing` flag, and a link to a movie or episode   |
| `streams`                      | ffprobe video, audio, and subtitle tracks per file                                                           |
| `subtitles`                    | Embedded, sidecar, or OpenSubtitles tracks and the path of their cached WebVTT                               |
| `playback_state`               | Per user, per item position, duration, and watched flag                                                      |
| `settings`                     | Key-value store for TMDB, OpenSubtitles, and IPTV credentials and other admin settings                       |
| `live_categories`              | Provider categories for live channels (and later VOD and series), keyed by provider id                       |
| `live_channels`                | Live channels keyed by provider stream id: name, number, logo, category, guide id, catch-up availability     |
| `live_programmes`              | Guide entries per guide channel id with start and end times; replaced wholesale on each refresh              |
| `iptv_movies`                  | Provider VOD titles keyed by stream id: provider name, parsed title and year, TMDB match, artwork keys       |
| `recordings`                   | Live recordings: channel, title, programme, planned and actual times, state, file path, size, duration       |
| `iptv_series`, `iptv_episodes` | Provider series with TMDB match; episodes are pulled from the provider when a series is opened, cached a day |

Items link to files one-to-many, so several versions of a movie or episode are allowed. Files that vanish are flagged `missing` rather than deleted so watch state survives a move.

## API shape

All routes live under `/api`. Every named zod schema in `server/src/schemas/` carries a `meta({ id })` and is emitted under `components.schemas`, so the contract already shows the v0 shapes for auth, libraries, items, playback, and progress even though only `/api/health` is routed today. The document declares a `bearerAuth` security scheme; enforcement arrives in sub-phase 1.2.

Schemas in brief:

- `common` — `LibraryKind` (`movie | tv | anime`), `ItemKind` (`movie | show | season | episode`), pagination helpers, `ErrorResponse`.
- `auth` — `Profile`, `SetupStatus`, `SetupRequest`, `LoginRequest` (profile id + 4 to 6 digit PIN + device name), `LoginResponse`, `Session`.
- `libraries` — `Library` with one or more paths and a kind, `CreateLibraryRequest`, `ScanStatus`.
- `items` — `ItemSummary`, `ItemDetail` (with `files`, `children`, TMDB and AniList ids), `MediaFile` and `StreamInfo` from ffprobe, `ItemsQuery`, `FixMatchRequest` with an anime `seasonOffset`.
- `playback` — `DeviceProfile` (containers, codecs, max width and bitrate, `ts | fmp4` HLS segments), `PlaybackDecideRequest`, `PlaybackDecision` (`direct | remux | transcode`, URL, session id, reason, subtitle URLs), `ProgressUpdateRequest`.

## Test fixtures

`scripts/make-fixtures.sh` generates deterministic media with ffmpeg so integration tests never depend on real downloads:

| File                                                               | Purpose                                                 |
| ------------------------------------------------------------------ | ------------------------------------------------------- |
| `movies/Sample Movie (2019)/Sample Movie (2019).mp4`               | h264 + aac, Plex naming, direct play everywhere         |
| `tv/Sample.Show.S01E02.1080p.WEB.H265-GRP.mkv`                     | hevc + ac3 + embedded srt, scene naming, transcode case |
| `movies/some.random.download.2021.x264-NOGROUP.mp4`                | no episode markers, needs-review case                   |
| `anime/[SubGroup] Sample Anime - 13 [1080p][HEVC][Dual-Audio].mkv` | fansub naming, jpn + eng audio, embedded ASS            |
